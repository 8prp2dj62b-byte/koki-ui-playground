Navigation component layer · no mockup inheritance

Navigation is orientation, not decoration.

Този слой е построен от frozen foundations и frozen Core Controls. Старите KOKI headers, docks, tabs и menus не са visual input. Навигацията има три задачи: да покаже къде си, как се връщаш и кои са стабилните destinations.

Candidate · review before freeze

Core principles

Stable destinationsPrimary navigation contains only durable product areas, never transient tasks or status filters.
One selected stateWithin one navigation group exactly one destination may be current.
Text carries meaningIcons accelerate recognition but labels remain visible for primary navigation.

Inherited contract

Geometry4px grid, frozen radii and ≥44px targets.
Iconography20px outline-first glyphs, 1.75px optical stroke.
SurfaceNavigation sits on Surface with divider; no static shadow.
MotionLocal selection uses 180ms; stack transitions use frozen spatial motion only when navigation context actually changes.
App Bar

The app bar anchors the current context.

App Bar contains current title/context and only globally relevant or local high-frequency actions. It does not become a dumping ground for every available action.

TitleCurrent task or object, one line where possible; truncates before actions collapse.

Bottom Navigation

Mobile destinations stay stable.

Bottom Navigation is reserved for the small set of durable top-level areas. It is not a toolbar and does not change because a conversation status changes.

Current area

Sample labels demonstrate semantics only; visual treatment is new.

CountPrefer 3–5 stable destinations. More belongs in another hierarchy.
SelectedCobalt icon + label. No capsule, floating blob or animated indicator required.
Safe areaBottom inset is respected without changing the visual grammar.
Desktop Rail

Desktop keeps the same destinations with less horizontal noise.

The rail is the desktop expression of the same primary navigation model, not a separate information architecture.

Primary workspace

The selected destination changes locally; content hierarchy is not restyled.

Rail rolePrimary destinations only. Object-level navigation belongs inside the workspace.
SelectedSubtle surface + Cobalt content; still elevation 0.
LabelsVisible in this compact rail because product areas must remain explicit.
Tabs

Tabs switch peers, not hierarchy.

Tabs are for views at the same hierarchy level. They do not replace primary navigation and do not masquerade as filter pills.

Обобщение · peer view
Peer onlyAll tabs belong to one object/task context.
UnderlineSelected state uses the frozen Cobalt signal; no filled pill treatment.
OverflowHorizontal scroll preserves labels on narrow screens; do not shrink substantive text.
Back & Breadcrumb

Return paths are explicit.

Back is an action in stack navigation. Breadcrumbs are orientation for wider/deeper desktop contexts. They are related, but not interchangeable.

Back

MeaningReturn to the previous stack context.
PlacementPredictable leading position; icon + text where ambiguity exists.

Breadcrumb

MeaningShow hierarchy, primarily on wider desktop contexts.
DepthKeep concise; collapse intermediate levels rather than wrapping into noise.
Responsive composition

One information architecture, different placement.

Responsive behavior changes where navigation lives, not what destinations mean. The same destination must not receive a new visual identity on another viewport.

PhoneBottom Navigation for stable primary destinations; App Bar for current object/task and local actions.
TabletRail may replace bottom navigation when width and interaction mode support it; content hierarchy remains unchanged.
DesktopPersistent rail + contextual App Bar/Breadcrumb where needed. Tabs remain inside the current object/task.
TransitionViewport change does not animate navigation between placements; layout adapts directly.
State contract

Navigation has a small, shared state vocabulary.

DefaultInk-3/Ink-2 content on Surface. No decorative background.
SelectedCobalt ownership signal; optional Subtle local background only where the component anatomy requires a block target.
HoverPointer-only Subtle feedback; never carries selection meaning.
FocusVisible frozen focus ring; independent of selected state.
DisabledRare for navigation. Prefer hiding destinations that cannot exist rather than showing dead navigation.
Badge/attentionNot defined in this layer. Counts/severity require the future feedback/status component, not ad-hoc dots.
Platform adapter

Core orientation stays; mechanics respect the platform.

iOSRespect safe areas and back-gesture expectations. Any translucency belongs to the future platform adapter, not Core Navigation.
AndroidRespect system back/predictive-back expectations and 48px targets where required.
Web / PWAPersistent rail on wide layouts, hover where a pointer exists, keyboard focus always visible.
AllSame destinations, labels, selected semantics and KOKI icon grammar.
Governance

Navigation cannot become screen-specific chrome.

Allowed

ComposeFrozen controls, icons, typography, surfaces, spacing and motion.
Adapt placementBottom nav ↔ rail according to viewport/platform.
Use contextApp Bar, Back and Breadcrumb express real navigation relationships.

Not allowed

Mockup inheritanceNo previous KOKI header, dock, tab or menu styling survives automatically.
Per-screen nav styleSELL, BUY, Dashboard or Profile cannot invent their own navigation grammar.
Decorative selected stateNo blobs, floating capsules, glow or oversized active backgrounds.
Status inside navNo ad-hoc red dots/count pills until Feedback & Status defines them.
